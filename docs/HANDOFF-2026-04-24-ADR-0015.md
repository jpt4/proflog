## Branch Outcome

This branch completes the separation between:

- the pure proof kernel in `src/proflog/kernel.clj`,
- and the answer-oriented execution overlay in
  `src/proflog/answer_overlay.clj`.

The split is now explicit in code, tests, ADRs, lessons, and worked examples.

## What Changed

### Code

- `src/proflog/kernel.clj`
  - now exposes only the ordinary proof-search surface,
  - no longer exposes answer-mode entry relations.
- `src/proflog/answer_overlay.clj`
  - owns answer-mode execution:
    - existential-as-variable behavior,
    - residual call deferral,
    - call-depth-controlled recursive answer descent,
    - top-level literal answer entry relations.
- `src/proflog/kernel_support.clj`
  - new shared support namespace for proof-core branch mechanics:
    - structural `L-ground`,
    - complementary literal closure,
    - disequality pruning,
    - proof-variable-only disequality closure,
    - bounded fuel stepping.
- `src/proflog/answers.clj`
  - routes answer search through `answer_overlay`.

### Tests

- `test/proflog/answers_test.clj`
  - locks the answer API to the overlay path.
- `test/proflog/query_test.clj`
  - new regression proving `query-succeeds` / `query-fails` stay on the pure
    kernel path.

## Current Architectural Reading

The repo now has three layers worth naming explicitly:

1. `kernel.clj`
   - ordinary proof search only.
2. `kernel_support.clj`
   - proof-core mechanics shared by both pure proof and answer export.
3. `answer_overlay.clj`
   - answer-specific search/export behavior.

This is the right boundary to preserve while ADR-0014 continues. It keeps the
question "can the pure prover do this?" separate from "can the answer surface
export this?".

## Most Important Next Opportunities

### 1. Continue ADR-0014 on the isolated pure kernel

Now that the pure kernel is cleanly separated, the next meaningful probes are:

- `GV`
- `FD`
- any remaining legacy-unsatisfied families

The key classification remains:

- absent from raw pure-kernel stream,
- present late in the raw stream,
- generically recoverable above the stream,
- or only reachable by specialty handling.

### 2. Simplify the remaining overlay-only mechanics

The overlay still contains its own `prove-stateo`. That is acceptable for now,
but the remaining answer-specific mechanisms should be challenged one by one:

- residual call storage,
- defer-vs-descend policy,
- existential-as-variable behavior,
- top-level literal answer entry.

The right question is no longer "should the kernel and answer mode be split?".
That is done. The new question is "which remaining overlay behaviors are truly
necessary?".

### 3. Keep `kernel_support.clj` honest

Anything moved into `kernel_support.clj` is effectively proof-core logic. Treat
changes there like kernel changes:

- add regressions,
- run both fast and extended suites,
- and assume both the kernel and overlay semantics may move.

## Suggested First Move For The Next Developer

Use the isolated kernel boundary to resume ADR-0014 with a promoted hard family
probe, starting from the pure query path and only layering answer export after
the raw behavior is measured.
