# ADR-0066: SJAS Finite Substitution Relation

- Status: completed
- Date: 2026-05-14
- Branch: `adr-0066-sjas-subst-relation`
- AAR: [AAR-0066](../aar/AAR-0066-sjas-subst-relation.md)

## Context

ADR-0065 corrected the Level-1 `SelfCons1` fixed-point argument by generating
the skeleton code used in `subst-prf/4`. Its implementation still keeps the
substitution boundary inside `subst-prf/4` entries of the form:

```text
system-code, substitution-code, theorem-code -> substituted-code
```

That shape is too specific. Willard's Appendix A separates `Subst(g,h)` from
`SubstPrf^d_beta(g,t,p)`: `g` identifies the formula skeleton, `h` is the
substituted sentence, and `t` is the theorem whose proof is being checked. The
substitution relation must not depend on the theorem code.

## Decision

Promote the finite generated substitution boundary into an explicit
object-language relation:

```text
subst-code(source-code, substituted-code)
```

For the current finite `IS#_D(beta)` substrate, generated entries are:

- identity substitutions for closed generated formulas;
- the Level-1 fixed-point substitution
  `selfcons-skeleton-code -> group-three-code`.

Then make `subst-prf(system-code, substitution-code, theorem-code, proof-code)`
consult `subst-code(substitution-code, substituted-code)` and prove
`theorem-code`, not `substituted-code`. The system code still selects the active
reflected system and prevents substitution facts from floating between systems.

This is still not an arbitrary parser for every possible code term. It is the
finite-system `Subst` relation needed by the generated `IS#_D(beta)` proof
profile, with a public predicate and a cleaner separation from proof checking.

## Consequences

- Users and tests can query the finite substitution relation directly.
- `subst-prf/4` no longer requires the theorem code to be the same as the
  substituted code.
- The fixed-point Group-3 path still works with `sjas-axiom` certificates.
- The remaining larger gap is a fully general Delta-star-0 code parser and
  substitution evaluator for formula codes not generated by the current finite
  system.

## Test Obligations

- A red test must show that `subst-prf(system, selfcons-skeleton-code,
  beta-code, sjas-axiom-certificate)` currently fails because the substitution
  table is tied to `group-three-code`.
- `subst-code(selfcons-skeleton-code, group-three-code)` succeeds.
- `subst-code(beta-code, beta-code)` succeeds for an ordinary closed formula.
- `subst-code(system-code, group-three-code)` fails.
- The existing identity and fixed-point `subst-prf/4` tests remain green.
- The focused SJAS, fast, and extended suites pass and record runtimes.
