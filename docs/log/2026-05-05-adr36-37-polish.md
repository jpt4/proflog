# ADR-36/37 Polish Before Main Integration

Date: 2026-05-05
Branch: `adr-0037-core-logic-minikanren-enhancements`

## Scope

This pass addresses the pre-integration requirement that ADR-36/37 should not
enter `main` with only a thin `absento` shim and narrow fuel-replacement probes.

## Changes

- Replaced the direct `treec`-based `absento` wrapper with a project-owned deep
  absence constraint in `proflog.minikanren-constraints`.
- Kept delayed checking over open subterms while adding tests for:
  - canonical `absento` residual reification;
  - open target variables;
  - same-variable target/node rejection before and after aliasing;
  - compound targets;
  - vectors;
  - map keys and values;
  - upstream push-down orderings.
- Moved `proflog.relational-arithmetic-upstream-test` off its test-local
  `symbolo` and `absento` helpers and onto the shared ADR-37 overlay.
- Expanded relational fuel adapter coverage for:
  - small ground finite fuel boundaries in both directions;
  - host-entry fuel chains that continue internally as bit-list numerals;
  - kernel proof parity across direct closure, beta, gamma, and delta formulas;
  - direct query success/failure parity across finite fuel slices;
  - existing answer-mode partial/reverse/composed query export parity.
- Added `proflog.relational-fuel-performance-probe` and a
  `probe-relational-fuel-performance` alias to compare finite-domain fuel with
  the relational-arithmetic adapter in one warmed JVM.

## Remaining Boundary

The relational arithmetic fuel adapter is still an opt-in/profiled candidate,
not a production replacement. Ground public entry fuel remains host integer or
`nil`, but direct open finite fuel synthesis exposes internal bit-list numerals
and symbolic bit-list families. Promoting this path to production still requires
an explicit public representation decision for direct fuel synthesis. The
performance probe does not block the profile: direct one-step calls are
significantly slower, but measured integrated Proflog surfaces stayed close
enough to make the semantic simplification worth preserving as the preferred
candidate.

`symbolo` and `numbero` remain `predc`-backed compatibility relations. Native
positive type constraints and type/absence store normalization remain a later
ADR-37 slice.
