# SJAS Diagonalization Efficiency Question

Date: 2026-05-20

## Verbatim Note

```text
Re Experiment D, Willard already demonstrates that FOL+U-Grounding is undecidable by implementing Turing Machine evaluation predicates within an SJAS. Regarding an object language of structures such as words or trees, which may not require arithmetization in order to reason over proofs of the same: Willard parametrizes the family of SJAS varieties not only by their axiom basis, but their deductive apparatus, and it is the specifics of the deductive apparatus that must be simulated by the proof predicate, in order to determine whether or not a proof exists. For example (correct me if I am not fully correct, interrogating the following with exacting rigor): tableau proofs generate proof objects that may be larger than Hilbert proofs, insofar as the number which codes a given tableau proof may be larger than that of a corresponding Hilbert proof of the same sentence. To build the Goedel sentence G stating that "it is provable in theory T that G is not provable in T", a number encoding this sentence, #G, must be built; #G is built by a composition of arithmetic operations, i.e., a term, term(#G). term(#G) must itself be encoded as a number #term(#G) in the sentence G, so as to make #G available to the proof predicate for manipulation. The diagonalization predicate usually allows for #G and #term(#G) to coincide, but because the U-Grounding language cannot build numbers fast enough, lacking a total functional multiplication primitive, #G grows faster than #term(#G). If #term(#G) grew faster than #G, than any system able to build #term(#G) could also build #G. If #G grew faster, then no matter how fast #term(#G) grows, it is guaranteed it will not build #G. #G cannot be built directly, only via some term construction term(#G), so if #term(#G), the number corresponding to the construction of the number of G, cannot be built such that it building it the number of G can also be built, then the diagonalization fails. [Alternative proferred explanation: term(#G) builds some number #G', and the diagonalization predicate usually ensures #G' and #G coincide. However, absent total multiplication, as term(#G) compounds in its efforts to build #G, the size of #G increases. term(#G) needs to build #G' fast enough to coincide with #G, and thus satisfy the diagonalization fixed-point, but the combination of language expressivity (including term-level representation of numerals) and deductive apparatus _prevents_ #G' from being built fast enough (as measured by "largest number that can be built using a given set of term builders", a kind of "arithmetic efficiency").]
```
