## Question

Can the current Proflog kernel be used as the SJAS proof predicate, by decoding
an SJAS proof code to a Proflog proof term and calling `kernel/prove-programo`,
while still preserving the invariants needed for Willard-style
self-justification?

This note attempts the proof in the style of a mathematics paper. The result is
negative for the current full implementation. A restricted positive theorem is
plausible, but it requires a sharply bounded fragment and additional
formalization.

## Source Boundary

The relevant literature gives two different facts that must not be collapsed.

Fitting's Proflog paper supplies a sound and complete tableau-style operational
semantics for logic programs. It defines ordinary semantic tableaux, adds
equality rules, adds a Procedure Call Rule for positive and negative ground
atoms, and proves agreement with the smallest supervaluation model. This is
strong evidence that Proflog-style procedure calls are a legitimate tableau
deductive apparatus when that apparatus is explicitly selected.

Willard's SJAS literature imposes the stricter condition. The
consistency-preservation results for `IS_D` and `IS#_D(beta)` are tied to the
deductive method `D`. In the 2013 paper, Willard records positive preservation
for semantic tableaux and Tab-1, and warns that slight strengthening can make
the preservation theorem fail, including Tab-2 and Hilbert-strength variants.
The proof predicate and the proof-size behavior of `D` are therefore part of
the theorem, not replaceable implementation detail.

The local Track 2a notes add the project-specific refinement: Willard's exact
curly-brace proof byte layout is probably irrelevant under an injective natural
translation, but the proof object must determine a finite inspectable tableau
tree and satisfy the lower-bound/anti-compression role of the Conventional
Tableaux Encoding Requirement.

## Candidate Theorem

Let `S` be a covered SJAS system code, `F` a theorem code, and `P` a proof-code
term decoded to a Proflog proof certificate. Let `Target(S,F)` be the formula
constructed by decoding `S` to the axiom basis and decoding `F` to the negated
theorem target.

The desired theorem is:

```text
kernel/prove-programo(Target(S,F), P)
iff
SJAS_TableauProof(expand(P,S,F), S, F)
```

with preservation of:

- finite tableau tree shape;
- root, formula node, child, ancestor, leaf, closure, and deduction facts;
- axiom-basis membership from encoded system code;
- quantifier witnesses and parameter freshness;
- equality/procedure/profile rules, either primitive or macro-expanded;
- proof-code inspectability;
- proof-size lower bound.

## Lemma 1: Ordinary Kernel Derivations Are Tableau-Shaped

For the ordinary fragment generated by `conj`, `split`, `univ`, `witness`,
`savefml`, complementary atom closure, and `false-close`, the kernel relation
has the shape of a semantic-tableau proof.

Proof sketch. Inspect `prove-stateo`, which delegates to `close-agendao` and
then selects a focused formula plus pending branch work. The `conj` clause maps
an alpha formula to one branch continuation containing both conjunctive
obligations. The `split` clause creates two sibling obligations. The universal
and existential clauses instantiate the quantified body and recurse on the
resulting child formula. Atom closure checks complementary literals already
saved on the branch. Induction on the successful kernel derivation gives a
finite proof tree whose recursive subproofs are the child/subsidiary trees.

This proves a structural adequacy result for the ordinary tableau skeleton. It
does not yet prove SJAS adequacy, because the witness terms live in branch
state and must be reconstructed in the object-level proof tree.

## Lemma 2: Search Order, Agenda Order, and Fuel Are Not Intrinsic

If the mathematical relation is defined existentially over successful
derivations and sufficient fuel, then agenda selection, rule trial order, host
data structures, and finite search bounds do not by themselves change the
accepted proof object.

Proof sketch. The proof object is the successful derivation tree, not the failed
branches explored before finding it. A fairer or less fair agenda can alter
runtime discovery, but if it validates the same ground proof certificate
against the same branch states, the accepted derivation is unchanged. Finite
fuel is similarly irrelevant only if it is treated as an evaluator bound and
not as part of the mathematical proof predicate.

This lemma is conditional. It fails if bounded fuel is built into the object
predicate or if agenda changes alter which certificates are accepted.

## Lemma 3: Procedure Calls Are Sound Only for an Explicitly Extended `D`

Proflog procedure-call constructors preserve a Fitting-style P-tableau
invariant if the selected SJAS deductive apparatus `D` includes Fitting's
Procedure Call Rule.

Proof sketch. Fitting's rule closes a branch containing a ground atom by
opening a closed tableau for the matching clause body, and closes a branch
containing the negated ground atom by opening a closed tableau for the negated
clause body. The Proflog kernel's `pos-call` and `neg-call` clauses do exactly
that after equality-walking the atom and checking L-groundness. The subsidiary
subproof is recorded as the child of the call constructor. Therefore, relative
to Fitting P-tableaux, these constructors have a plausible direct rule
correspondence.

But this is not the same as preserving Willard's plain semantic-tableau `D`.
If `D` is the ordinary Willard candidate-tree apparatus over reflected axioms,
a Proflog call is a macro over:

1. citing the reflected Group-2b axiom from encoded `S`;
2. instantiating the universal binders;
3. applying implication/polarity tableau rules;
4. continuing with the body or negated body.

Current code does not prove this expansion, and does not prove its proof-size
lower bound. Thus procedure calls are acceptable only under a selected-D
primitive-rule theorem or under a future macro-expansion theorem.

## Lemma 4: Equality and Profile Rules Are Not Yet Fully Matched

The kernel's equality and profile rules are semantically motivated, but not yet
fully matched to the SJAS proof predicate.

Proof sketch. Fitting includes equality rules, including reflexivity,
substitutivity, free closure, and one-one reasoning. The Proflog kernel has a
free-constructor equality layer with explicit substitution, disequality store,
closure, and equality-triggered procedure calls. The SJAS profile additionally
has arithmetic equality/relations over U-Grounding numerals and code-reading
rules.

The arithmetic/profile rules are plausible object-language work because they
are miniKanren relations over terms and codes. The generic free-constructor
and equality-triggered procedure-call constructors, however, are not yet
classified as SJAS primitives or macro-expanded over the selected SJAS `D`.
Some proof tags emitted by current paths are also outside the proof-code
alphabet. Hence equality/profile preservation remains an obligation, not a
proved invariant.

## Lemma 5: The Current Certificate Does Not Preserve the Proof-Size Invariant

The current proof-predicate shortcut fails the strongest SJAS invariant:
proof-size anti-compression.

Proof sketch. Willard's proof predicate is sensitive to the encoded proof
object. The proof code must determine an inspectable semantic-tableau tree, and
its size must grow with the formula/function-symbol occurrences in that tree.
Current Proflog proof codes encode proof constructors and subproof shape. The
formula at a node, the theorem code, the system axiom basis, reflected clause
bodies, substitutions, and some quantifier instantiations are reconstructed
from `(S,F)` and kernel branch state rather than carried in the proof-code
payload.

This creates families of compact certificates whose expansion can contain
arbitrarily large formula content. The clearest example is axiom citation:
`sjas-axiom` is a fixed small proof-code object, while the cited formula can be
large and is supplied through `S` and `F`. Procedure calls have the same shape:
a compact `pos-call` or `neg-call` can stand for a reflected axiom
instantiation and a clause-body tableau whose formula content lives in the
program/system code.

This may be a good executable certificate format, but it is not yet a proven
Willard-compatible proof encoding. It is compatible only if one proves that the
actual proof object is an expanded formula-bearing tree `expand(P,S,F)`, and
that the size measure used in the self-reference theorem is applied to that
expanded object or is otherwise bounded below by the certificate plus encoded
context. No such theorem currently exists.

Therefore the current shortcut cannot be said to preserve the SJAS
self-justification invariant.

## Main Result

### Theorem

The current Proflog kernel shortcut is not yet a faithful SJAS proof predicate
for the full current SJAS implementation.

### Proof

Assume for contradiction that the shortcut is faithful. Then every accepted
non-`sjas-axiom` `tableau-proof/3` or `subst-prf/4` certificate, after decoding
and `kernel/prove-programo` validation, must correspond to an SJAS semantic
tableau proof preserving the Track 2a relevant invariants.

By Lemma 1, ordinary kernel derivations give a strong partial match for
tree-shaped tableau structure. By Lemma 2, runtime search order and fuel can
be ignored under the usual sufficient-fuel interpretation. By Lemma 3,
procedure calls can be made sound only if admitted as Fitting P-tableau
primitives or macro-expanded over reflected axioms. By Lemma 4, equality and
profile rules still require primitive, macro, reachability, or exclusion
lemmas.

But Lemma 5 gives a direct failure of a relevant invariant: current proof codes
do not by themselves encode formula-bearing tableau trees with the required
anti-compression behavior. Since Willard's positive preservation theorem is
sensitive to the selected deductive method and fails for stronger or more
compressed proof mechanisms, theorem-level agreement is insufficient. The
faithfulness assumption therefore lacks the required proof-size and
proof-object preservation lemmas.

The contradiction is not that the kernel is unsound as a theorem prover. The
contradiction is that SJAS self-justification requires a proof predicate whose
intensional proof objects have the right structure and size behavior. Current
`kernel/prove-programo` validation has not been shown to provide that.

So the shortcut is not yet justified for the full SJAS claim.

## Restricted Positive Theorem

A restricted theorem should be provable with additional work:

```text
For a fragment C0 whose certificates use only ordinary encoded tableau
constructors, whose quantifier witnesses are reconstructible from branch state,
whose equality/profile/procedure constructors are either absent or explicitly
primitive, and whose proof object is measured after formula-bearing expansion:
  Proflog kernel acceptance corresponds to SJAS tableau acceptance.
```

The proof would be by induction on the kernel derivation:

- `conj` maps to alpha extension;
- `split` maps to beta branching;
- `univ` maps to gamma instantiation with reconstructed term;
- `witness` maps to delta instantiation with reconstructed fresh parameter;
- saved-literal closure maps to branch closure;
- admitted SJAS arithmetic/code rules map to object-language profile rules;
- each primitive or macro-expanded call/equality rule is handled by its own
  lemma.

This theorem would justify the kernel bridge for `C0`, not for every current
SJAS proof path.

## Verdict

The Proflog kernel is a strong candidate implementation substrate. It is
tableau-shaped, proof-producing, and well aligned with Fitting's logic
programming literature. It is not merely an arbitrary host evaluator.

However, as currently used inside `tableau-proof/3` and `subst-prf/4`, it does
not yet faithfully preserve all invariants needed for Willard-style
self-justification. The decisive gaps are:

- no completed formal correspondence between kernel derivations and the SJAS
  formula-bearing proof-tree predicate;
- no anti-compression theorem for skeletal proof certificates;
- unresolved primitive or macro status for procedure calls, generic equality,
  guarded calls, and some profile rules;
- proof-code alphabet gaps for emitted proof evidence;
- quantifier witness reconstruction not yet formalized.

Therefore, using `kernel/prove-programo` as a proof-predicate shortcut is
operationally defensible and probably sound over a restricted fragment, but it
is not yet a completed justification of the SJAS self-justification invariant.
